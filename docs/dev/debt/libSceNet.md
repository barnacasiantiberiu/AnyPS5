### Functional

- [sceNetSetsockopt](../../../core/libs/prx/libSceNet/Export.cpp) (libSceNet) sets `SO_RCVTIMEO` and `SO_SNDTIMEO` as the host socket's timeouts. On Windows a receive or send on a stream socket that times out fails with `ETIMEDOUT`, where FreeBSD returns `EAGAIN` or the partial count: Winsock leaves the connection in an indeterminate state after a timeout and reports no partial count ([SOL_SOCKET options](https://learn.microsoft.com/en-us/windows/win32/winsock/sol-socket-socket-options)), so FreeBSD's behaviour needs the timeout waited for without the host option. A receive on a datagram socket that times out fails with `EAGAIN`
- [sceNetSendmsg and sceNetRecvmsg](../../../core/libs/prx/libSceNet/Export.cpp) (libSceNet) copy the scatter/gather list through one host buffer and accept only the flags `sceNetSend`/`sceNetRecv` accept. Sending control data throws; a receive never returns control data (`msg_controllen` 0), since no socket option that queues it is supported
- [sceNetResolverAbort and sceNetResolverStartNtoaMultipleRecords](../../../core/libs/prx/libSceNet/Export.cpp) (libSceNet) follow [shadPS4 net_resolver.cpp](https://github.com/shadps4-emu/shadPS4/blob/811bfcd7d17ed8ae975c477d9ff28abc744e1ca8/src/core/libraries/net/net_resolver.cpp) and [net.cpp](https://github.com/shadps4-emu/shadPS4/blob/811bfcd7d17ed8ae975c477d9ff28abc744e1ca8/src/core/libraries/net/net.cpp), adapted from [PR #3728](https://github.com/boykopovar/AnyPS5/pull/3728). Abort flags 1 and 2 preserve one cancellation for the next forward or reverse lookup when none is running. A running host lookup cannot be interrupted: cancellation is reported as EINTR after it returns, without writing the result. Other flag bits throw; multiple-record flags, including asynchronous requests, remain unsupported as for the Ex form. Timeout/retry arguments remain ignored by the synchronous host resolver. Guest layout, error precedence and cancellation behavior remain unverified on console. PC tests use numeric IPv4 loopback, exact 384-byte results, output guards, invalid inputs, independent resolver state and repeated lifecycles. Existing network tests also cover localhost DNS and sockets. Cancellation racing an active host lookup, resolver destruction during a lookup and allocation failures are not deterministically tested.
