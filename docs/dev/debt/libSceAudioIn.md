# libSceAudioIn technical debt

### Silent stubs

- [sceAudioInInit](../../../core/libs/prx/libSceAudioIn/Export.cpp) (libSceAudioIn) - returns 0 without library-wide setup, as `sceAudioOutInit` does; each `sceAudioInOpen` opens its own SDL capture device

### Unknown function info

- [sceAudioInIsPadEmbeddedMic](../../../core/libs/prx/libSceAudioIn/Export.cpp) (libSceAudioIn) takes `int32_t handle`, following the Ghost of Yotei (PPSA26344) call site in #2355. It validates allocated ports under the audio mutex, returns INVALID_HANDLE (0x80260101) for invalid/closed ports and zero for host capture ports. Zero is interpreted as not a controller-embedded microphone; the host backend has no DualSense device classification, and the console result/error convention remains unverified. Adapted from [PR #4507](https://github.com/boykopovar/AnyPS5/pull/4507). PC tests use file-backed PCM capture and no-device ports, sample guards, every slot, handle reuse, invalid bounds and concurrent query/close.

### Functional

- [Capture modes](../../../core/libs/prx/libSceAudioIn/Export.cpp) share eight ports but retain distinct input behavior. Ordinary Open preserves fixed 128/256-frame reads at 16/48 kHz. HqOpen accepts 128 frames at 48 kHz, waits one grain and drains available complete frames, up to 384. AsyncOpen accepts positive grains through 384 at 16/48 kHz and polls queued PCM without waiting for a full grain, returning 0 if none is available. HQ/async callers must provide space for 384 frames in the selected format and use the returned frame count; bytes beyond that count are untouched. A null destination clears the capture queue. The SDL device quantum is rounded up to a power of two, at least 128, independently of the guest grain.
- [Formats and limits](../../../core/libs/prx/libSceAudioIn/Export.cpp) follow the signed-16 and float mono/stereo formats, HQ restriction and async maximum described by [SharpProspero AudioIn.cs at 5dfdb4b](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/src/SharpProspero/Interop/Audio/AudioIn.cs). Format 0x10 aliases float mono as in [KytyPS5 audio.cpp at df5b9b9](https://github.com/KytyPS5/KytyPS5/blob/df5b9b92be7dfd463b47756b707d6d356a9f0550/src/libs/audio.cpp). HQ validation, its one-grain delay and maximum 384-frame drain also follow that implementation. Invalid type/index/size/rate/format return the existing AudioIn errors before allocating a port. Queued data beyond four maximum blocks is discarded in complete frames to limit latency.
- [PC validation](../../../core/libs/prx/libSceAudioIn/Export.cpp) uses the bundled SDL disk capture driver with generated signed-16 and float PCM files. Tests compare captured bytes, protect both buffer boundaries and the unwritten suffix, exercise all five format values, validate async size boundaries including 1 and 384, and cover all eight exports, port exhaustion, reuse, queue reset, concurrent busy reads and no-device behavior. No microphone, console, download or new runtime dependency is required.

### Unverified behavior and host limitations

- [Timing and validation](../../../core/libs/prx/libSceAudioIn/Export.cpp) are explicit host policies, not measurements of the PS5 implementation. [PR #570](https://github.com/boykopovar/AnyPS5/pull/570) records disagreement between shadPS4's generic HQ forwarding and KytyPS5's restricted HQ mode. This implementation selects the restricted mode supported by SharpProspero and KytyPS5, returning INVALID_SIZE/INVALID_FREQ for rejected HQ profiles. SharpProspero documents the async upper bound but not every valid grain: acceptance of every positive grain through 384, immediate polling and zero-frame empty reads are host decisions. The 8/8 implemented-export count does not establish exact console timing, validation precedence or full title compatibility.
- [Unavailable recording devices](../../../core/libs/prx/libSceAudioIn/Export.cpp) retain ordinary fixed-grain silence and HQ one-grain silence; asynchronous input returns 0 without modifying the destination. GetSilentState reports whether a device opened, not hardware mute state or hotplug changes. User routing, voice processing and controller microphone classification are not modeled. Physical microphone capture and device loss remain unvalidated. The Module portability CI workflow exercises deterministic PCM capture and missing-device operation on clean Windows and Linux runners.
