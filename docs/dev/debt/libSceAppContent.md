# libSceAppContent technical debt

### Unknown function info

- [sceAppContentDownloadDataGetAvailableSpaceKb](../../../core/libs/prx/libSceAppContent/Export.cpp) (libSceAppContent) - a title whose `param.json` declares `downloadDataSize` 0 gets 0 KB and OK; the console's behaviour for a title without a download data area is unverified (it may return an error instead). KytyPS5 does not special-case it, and shadPS4 stubs 1048576 KB
- [sceAppContentAddcontEnqueueDownload and sceAppContentGetAddcontDownloadProgress](../../../core/libs/prx/libSceAppContent/AppContent.hpp) use the signatures and two-uint64_t progress layout in [SharpProspero 60977b29](https://github.com/SvenGDK/SharpProspero/blob/60977b29103452b9681ae10c7a9011d44965bf16/src/SharpProspero/Interop/AppContent/AppContent.cs). Installed status 4 and list/count behavior follow [shadPS4 d1f9594b](https://github.com/shadps4-emu/shadPS4/blob/d1f9594b9d1b903d14a26ada8995cf1db2cddc50/src/core/libraries/app_content/app_content.h). The installed-only host model returns success for an already installed enqueue request, reports the sum of regular-file sizes in both progress fields, and uses the existing PARAMETER and DRM_NO_ENTITLEMENT errors for invalid or absent content. These choices, exact-16-character label validation, duplicate-mount BUSY and error precedence are not console measurements; downloaded package bytes may differ from extracted file bytes on PS5.

### Functional

- [Additional content](../../../core/libs/prx/libSceAppContent/Export.cpp) uses the opt-in per-title `ANYPS5_ADDCONT_ROOT/<service>/<label>` catalog described in [BUILD.md](../BUILD.md). It supports installed local files only: no PSN transport, queued/partial downloads, package extraction, entitlement validation or keys. The catalog is separate from NpEntitlementAccess configuration and is fixed on first use; file sizes are read again for each progress query. Missing roots expose an empty catalog; malformed roots, removed data, filesystem errors and non-regular data entries fail explicitly. Host aliases permit writes and do not invalidate existing descriptors after unmount. Catalog discovery and filesystem access are not atomic against an external process modifying the content tree.
- [AppContent](../../../core/libs/prx/libSceAppContent/Export.cpp) [PC functional tests](../../../core/libs/tests/GuestAppContentAddons.cpp) exercise the guest entry points with generated files, exact byte totals, service isolation, truncated lists, guard bytes, repeat mounts, concurrent first access, invalid configuration recovery and removed directories. The existing storage suite covers the remaining exports. All 13 counted exports have host behavior; this is not PSN download support, PS5 equivalence, or proof that every title works.
- [Temporary app-content storage](../../../core/libs/prx/libSceAppContent/Export.cpp) tracks one `/temp0` mount, preserves its files on unmount, and rejects new path resolutions until remount. Mount, format, space-query and unmount errors follow [fpPS4](https://github.com/red-prig/fpPS4/blob/04cefd43e6fddd1ab033e7980cd356d14c964905/sys/sys_path.pas); the pointer ABI is also declared by [SharpProspero](https://github.com/SvenGDK/SharpProspero/blob/main/src/SharpProspero/Interop/AppContent/AppContent.cs). Existing open host descriptors remain usable after unmount; console behaviour with open files is unverified. Host filesystem failures still throw.
