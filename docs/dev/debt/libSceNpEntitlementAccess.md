# libSceNpEntitlementAccess technical debt

### Unknown function info

- [sceNpEntitlementAccessGetEntitlementKey](../../../core/libs/prx/libSceNpEntitlementAccess/Export.cpp) - the three-argument signature, 16-byte key and errors `0x817D0002`/`0x817D0007` follow [KytyPS5](https://github.com/KytyPS5/KytyPS5/blob/main/src/libs/libNet.cpp); PPSA01521 passes a service label, entitlement label and output pointer. Only the no-key path is implemented: local entitlement labels carry no keys, and the output is untouched on failure. Console error precedence and key provisioning are unverified
- [sceNpEntitlementAccess{Request,Poll}{Unified,Service}EntitlementInfo{,List}](../../../core/libs/prx/libSceNpEntitlementAccess/Export.cpp) - signatures unknown; no reference implements them, so they are declared without parameters. The single-item variants copy the behaviour of the list ones, with no source of their own. Like the consume requests in the same library, they report the signed-out NP state with `SCE_NP_ERROR_SIGNED_OUT` (`0x80550006`) and write nothing. PPSA15657 calls the unified request during start-up and continues past the error. Whether the console fails at the request or at the poll when signed out is unverified

### Functional

- [sceNpEntitlementAccessGetGameTrialsFlag](../../../core/libs/prx/libSceNpEntitlementAccess/Export.cpp) (libSceNpEntitlementAccess) - reports a full game, not a game trial: writes 0 to the `uint32_t` output and returns 0, and a null pointer returns `0x817D0002`. The single-pointer signature, the value, the one-word write and the error follow [sharpemu](https://github.com/sharpemu/sharpemu/blob/a2983692930564815a77f81e74c151268f5b935f/src/SharpEmu.Libs/Np/NpEntitlementAccessExports.cs#L98-L116); `0x817D0002` is the parameter error of KytyPS5, prosper and `sceNpEntitlementAccessGetEntitlementKey`, while `sceNpEntitlementAccessGetSkuFlag` here returns `0x80558003`. None of this is a console measurement, and PRAGMATA (PPSA02530) shows four live registers at the call, so further arguments are not ruled out

- [sceNpEntitlementAccessGetPftFlag](../../../core/libs/prx/libSceNpEntitlementAccess/Export.cpp) follows upstream [7900b59d](https://github.com/boykopovar/AnyPS5/commit/7900b59d52a1c010ea8ecd9542d6f0c32b587b3c): one uint32_t output, 0 for the existing full-game host policy, and parameter error 0x817D0002 for null. This avoids the previous throwing stub; it does not contact PSN or validate ownership. The pointer signature also matches the PPSA34063 caller described in [discussion #4275](https://github.com/boykopovar/AnyPS5/discussions/4275). The console error precedence and trial licensing remain unverified. The PC suite checks both trial flags and SKU output guards, local entitlement lists and lookups, null/unterminated inputs, malformed/missing configuration, concurrent first access, signed-out operations and unchanged key/transaction outputs. All 21 counted exports now have host paths, but the existing signed-out responses and no-op initialization/abort/delete behavior remain; this count is not online-service coverage.
