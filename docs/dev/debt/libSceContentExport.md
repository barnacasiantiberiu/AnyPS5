# libSceContentExport technical debt

### Functional

- [Content exports](../../../core/libs/prx/libSceContentExport/Export.cpp) copy files or callback-provided bytes into the guest root's `/_media/export-*/` directories. All four export entry points perform real byte transfers, with optional thumbnails and title/comment/media-type metadata. A temporary sibling directory is renamed only after every file closes successfully; failure and cancellation attempt to remove that operation's staging directory and leave the output path buffer unchanged. Existing exports and source files are preserved. The returned path is a guest path resolved through libc; this host media directory is not the console's media database or system UI.
- [The guest ABI](../../../core/libs/prx/libSceContentExport/Export.cpp) follows [SharpProspero ContentExport.cs at 5dfdb4b](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/src/SharpProspero/Interop/Content/ContentExport.cs) and the allocator/provider types in [shadPS4 content_export.h at 443f022](https://github.com/shadps4-emu/shadPS4/blob/443f022450f6857256e780daa3d5a14029a748f7/src/core/libraries/content_export/content_export.h). Providers receive data-address and size outputs plus user data; status 0 means more data and 1 finishes, including a final data-bearing chunk. The declared total is enforced. Negative/unknown statuses, null nonempty chunks, length mismatches and an empty in-progress chunk fail. Callbacks and allocator/free routines run outside the state mutex, allowing progress queries, cancellation and work in another session without deadlocking.
- [Session lifecycle](../../../core/libs/prx/libSceContentExport/Export.cpp) retains the ten-session limit and monotonically increasing positive ids. One export may run per session. Progress starts at 0, increases with bytes transferred (including a thumbnail), stays below 100 until publication and remains 100 after success. A session may be reused after success, error or cancellation. Cancel affects only a currently running export; finish rejects active work and term rejects live sessions. The caller's allocator supplies the copy buffer and its matching free routine releases it on success and failure; a zero configured buffer size selects a 64 KiB host default.
- [PC tests](../../../core/libs/prx/libSceContentExport/Export.cpp), in [GuestContentExport.cpp](../../../core/libs/tests/GuestContentExport.cpp), exercise all ten exports, exact binary output, file and callback thumbnails, metadata escaping, output guards, invalid inputs, every session slot, failed allocation, malformed providers, progress, concurrent sessions, cancellation from another thread and from the provider, rollback and retry. All four cases fail against the previous implementation and pass after restoration. The standard functional runner builds and tests this module; no external media files, downloads or extra runtime dependencies are required.

### Unverified behavior and host limitations

- [Host policy](../../../core/libs/prx/libSceContentExport/Export.cpp) supports the five media types named by the public binding: JPEG, PNG, GIF, MP4 and WebM. It copies bytes without decoding, transcoding or verifying the media payload. File-thumbnail type is inferred from a PNG/JPEG/GIF extension. The existing parameter layout names the middle 257 bytes `comment`; SharpProspero treats them as reserved. They are retained as metadata here, not sent to a console service.
- [Error and timing behavior](../../../core/libs/prx/libSceContentExport/Export.cpp) remains unmeasured on PS5. Invalid state, unsupported media types, I/O errors, cancellation and provider failures throw host exceptions rather than inventing guest error codes. Idle progress 0, cancelled progress retaining the last partial value, idle cancellation rejection, metadata filenames, default buffer size and zero-length export support are host policies. Calls are synchronous; progress/cancel may be invoked by another thread or a provider. Cancellation is cooperative between chunks and cannot interrupt a callback or host I/O operation that does not return. Providers must make progress and allocators/free callbacks must honor their contracts.
- [Persistence](../../../core/libs/prx/libSceContentExport/Export.cpp) preserves completed bundles across processes, but does not integrate with a native photo library. Rename publishes complete bundles during ordinary operation; it does not guarantee durability after power loss. A process crash can leave a private `.pending-*` directory. External source-file changes and hostile filesystem races are not a supported snapshot mechanism. Only the Windows PC runtime was executed for this change; clean-checkout setup, POSIX execution and console equivalence were not revalidated. A 10/10 implemented-export count does not establish those properties.
