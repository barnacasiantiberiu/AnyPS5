# libkernel_sys technical debt

### Functional

- [fchdir](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) changes the guest working directory to the descriptor's directory: on Windows through the path recorded when the descriptor was opened, on Linux through the `/proc/self/fd` link target. It returns `EBADF` for a descriptor that is not open and `ENOTDIR` for one that is not a directory. FreeBSD `change_dir`'s search-permission check (`EACCES`) is not modelled, and a directory renamed after it was opened is still reached through the recorded path. Console behaviour is unverified
- [openat](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) passes `AT_FDCWD` (-100) and absolute paths to `open`. Any other relative path is joined to the descriptor's host directory, found the same way as for `fchdir`, so guest path aliases and case-insensitive name matching do not apply to it, and a `..` component is not kept inside the guest root. It returns `EBADF` for a descriptor that is not open and `ENOTDIR` for one that is not a directory. `O_NOFOLLOW` rejects a final native or stored guest symbolic link; exclusive creation rejects existing links, including dangling ones. Intermediate guest links use the shared resolver. PPSA99003 opens directory entries this way. Console behaviour is unverified
- [pathconf](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) looks the path up as FreeBSD 11's `kern_pathconf` does (links followed, `ENAMETOOLONG` for a path of 1024 bytes or more or a component over 255) and returns the constants of FreeBSD 11's UFS `ufs_pathconf` for files and directories alike: `_PC_LINK_MAX` 32767, `_PC_NAME_MAX` 255, `_PC_PATH_MAX` and `_PC_SYMLINK_MAX` 1024, `_PC_PIPE_BUF` 512, `_PC_CHOWN_RESTRICTED` and `_PC_NO_TRUNC` 1, `_PC_FILESIZEBITS` 64, `_PC_REC_MAX_XFER_SIZE` -1, `_PC_PRIO_IO` and `_PC_SYNC_IO` 0. Whether the console's filesystems report the same is not verified. It throws for the names whose UFS value depends on the mount (`_PC_ALLOC_SIZE_MIN`, `_PC_REC_INCR_XFER_SIZE`, `_PC_REC_MIN_XFER_SIZE`, `_PC_MIN_HOLE_SIZE`), the kernel options (`_PC_ACL_EXTENDED`, `_PC_ACL_PATH_MAX`, `_PC_ACL_NFS4`, `_PC_MAC_PRESENT`) or the page size (`_PC_REC_XFER_ALIGN`), and on which UFS and `vop_stdpathconf` disagree (`_PC_MAX_CANON`, `_PC_MAX_INPUT`, `_PC_VDISABLE`, `_PC_ASYNC_IO`); other names fail with `EINVAL`
- [symlink](../../../core/libs/prx/libkernel_sys/Export.cpp) stores relative and absolute guest targets, including dangling targets. Absolute targets are resolved against the current guest root and mount aliases when accessed, not against the host drive root. Windows uses an empty file with an `AnyPS5.GuestSymlink.v1` NTFS alternate data stream containing a versioned target; creation publishes the initialized file without overwriting an existing entry. This works without native symbolic-link privileges. The stream follows rename and persists across fresh processes. Backups and copies must preserve named streams: ordinary host applications see an empty file and cannot traverse these guest links. Filesystems without named-stream support are unsupported. The stream mechanism follows [Microsoft's file-stream documentation](https://learn.microsoft.com/en-us/windows/win32/fileio/file-streams). POSIX uses native relative links and a reserved, hex-encoded target for absolute guest paths; host tools cannot follow that encoding. No external runtime files are required.
- [readlink](../../../core/libs/prx/libkernel_sys/Export.cpp) and `readlinkat` return the original guest target bytes, truncate to the supplied capacity and do not append a NUL. Shared libc resolution follows mixed native/guest chains and rejects more than 32 link traversals with `ELOOP`. `lstat`, directory enumeration, exclusive creation, rename, remove and unlink preserve final-link identity. Unmanaged Windows relative native links still use reparse data; absolute native links, junctions and other unrecognized reparse points remain unsupported because a host target has no unambiguous guest form. These branches must not be inferred to work from the export count.
- [libkernel_sys](../../../core/libs/prx/libkernel_sys/Export.cpp) is exercised by [GuestAbsoluteSymlinks](../../../core/libs/tests/GuestAbsoluteSymlinks.cpp), which tests actual file reads, target-byte/truncation boundaries, `stat`/`lstat`, both directory enumeration APIs, descriptor-relative access and creation, alias remapping/blocking, dangling links, cycles, exclusive/no-follow opens, rename/removal, and persistence in a fresh process. Windows PC validation exercises guest links without privilege-dependent skips. Two separate unmanaged native-link fixtures in `GuestKernelSys` remain unavailable on a Windows account without native-link privileges. Console behavior and the full POSIX runtime are unverified. Existing lexical `..` handling, descriptor rename tracking and filesystem races remain limitations; this is implemented-export coverage, not complete POSIX or game compatibility.
- [readlinkat](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) passes `AT_FDCWD` (-100) and absolute paths to `readlink`. Any other relative path is joined to the descriptor's host directory, found the same way as for `fchdir`, so guest path aliases and case-insensitive name matching do not apply to it, and a `..` component is not kept inside the guest root. It returns `EBADF` for a descriptor that is not open and `ENOTDIR` for one that is not a directory. Console behaviour is unverified
- [fork](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) uses native address-space cloning, owner preparation/rollback, inherited descriptors, shared child/session identity and wait/reap. The [Windows runtime](../../../core/libs/prx/libc/src/WindowsProcessRuntime.cpp) reconnects CSR servers 1 and 3 and refreshes USER32/IMM32 shared information before guest execution resumes. Its [layout profile](../../../core/libs/prx/libc/include/WindowsProcessLayout.hpp) is restricted to the exact x64 DLL identities documented below: ntdll/kernelbase/imm32 10.0.26100.9278 and user32 10.0.26100.8875. Exact Microsoft PDB GUID/age and checked export addresses identify the profile; other builds return `ENOSYS` before cloning. The profile uses four individually identified CSR fields, not the broad reset from the [WINNIE research implementation](https://github.com/sslab-gatech/winnie/blob/master/forklib/fork.cpp). Functional Windows tests exercise child memory independence/shared mappings, inherited file/directory positions, new threads, nested clones, time/path APIs, sessions, orphan identity, hook failures and handle cleanup. Arbitrary native USER/GDI continuation is unsupported: creating new GDI objects or windows after cloning still fails in isolated probes. Active GPU mapping/pin observers, external memory leases and unsafe callback/owner contention are rejected with `EAGAIN`; other inherited external runtimes and cross-process guest signaling remain outside this implementation. POSIX delegates to native fork; the internal recursive-owner repair algorithm was tested with native pthreads under Ubuntu WSL, but the complete C++ POSIX runtime was not built or run in this Windows session. Implemented-export counts do not establish console or universal host compatibility.
- [setsid](../../../core/libs/prx/libkernel_sys/Export.cpp) and [getsid](../../../core/libs/prx/libkernel/System/src/Process.cpp) use the shared guest process identity on Windows: the initial process leads its own group, a fork child inherits that group/session, and a non-leader can create a session. The group/session identifiers are guest metadata rather than Windows console or job identifiers. [umask](../../../core/libs/prx/libkernel_sys/Export.cpp) keeps the guest's mask (initially 022, masked to 07777) and returns the previous one; Linux named shared-memory creation applies it, but ordinary files are still created with the host process's mask.
- [mkdirat](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) delegates AT_FDCWD and absolute guest paths to existing mkdir. Relative paths validate the descriptor; Windows walks parent components before CreateDirectoryW, preserving ENOENT/ENOTDIR for missing or regular-file prefixes even before a .. component. Rooted Windows paths in the descriptor-relative branch return EINVAL. POSIX resolves stored guest link targets before calling native mkdir; this branch was not run in the Windows-only PC validation. Host errors use the existing guest error mapping. Windows mode bits, guest aliases and rename tracking follow the existing descriptor/path limitations; Windows path resolution remains subject to concurrent filesystem changes. Linux permissions use the host umask as existing ordinary file creation does. Console behavior is unverified. Adapted from [PR #4743](https://github.com/boykopovar/AnyPS5/pull/4743), with component validation and error mapping revised locally. PC tests verify actual directories, nested/relative/absolute paths, guest cwd, duplicate names, invalid or closed descriptors, unchanged existing files and no directory created through invalid prefixes.
