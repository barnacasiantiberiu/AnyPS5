# libSceContentDelete technical debt

### Functional

- [Deletion](../../../core/libs/prx/libSceContentDelete/Export.cpp) removes a completed host content bundle by its returned guest media-file path or persistent positive 64-bit content id. The bundle's media, optional thumbnail and metadata are removed; original sources and neighboring exports are retained. All four exports have functional PC tests. Initialization and termination serialize with deletion, and competing deletions have at most one successful caller.
- [Guest signatures](../../../core/libs/prx/libSceContentDelete/Export.cpp) follow [SharpProspero ContentDelete.cs at 5dfdb4b](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/src/SharpProspero/Interop/Content/ContentDelete.cs): ByPath accepts a UTF-8 string, ById a signed 64-bit id, and the initialization structure occupies 48 bytes on a 64-bit host.
- [Host ids](../../../core/libs/prx/libSceContentDelete/Export.cpp) use 64-bit FNV-1a over the complete ASCII `export-<digits>-<digits>` directory name, with the sign bit cleared and bit zero set. The algorithm is shared with content export, which records the decimal id as a JSON string in `metadata.json` to avoid JSON-number precision loss. Existing bundles without this field remain deletable. Id lookup scans disk rather than an in-memory index, survives reinitialization and process restarts, and rejects ambiguous matching names instead of selecting arbitrarily.
- [Validation](../../../core/libs/prx/libSceContentDelete/Export.cpp) accepts only a direct `/_media/export-*/content.<supported extension>` path. It rejects traversal, alternate separators, extra path components, thumbnail/metadata paths, unknown bundle files, nested directories, symbolic links and Windows reparse points. A complete flat bundle must contain one media file, one metadata file and at most one thumbnail. Every entry is checked before removal. Removal is nonrecursive; hard links are unlinked without deleting the other directory entry. Staging directories are not eligible for deletion.
- [PC tests](../../../core/libs/prx/libSceContentDelete/Export.cpp), in [GuestContentDelete.cpp](../../../core/libs/tests/GuestContentDelete.cpp), cover actual export-to-delete flows, source-byte preservation, metadata ids, a fixed legacy-id vector, lifecycle errors, stale ids/paths, invalid bundles and traversal, hard links, Windows file-sharing failure, real Windows junction rejection, and competing path/id deletion. They use isolated generated fixtures and need no downloads or external media. The dependent content-export suite is also run.

### Unverified behavior and host limitations

- [Host scope](../../../core/libs/prx/libSceContentDelete/Export.cpp) is the emulator's completed media bundles, not the PS5 media database. Host ids are not console database ids. `libSceContentSearch` still models an empty library and does not enumerate these exports; connecting that module to this store is separate work. Unsupported paths and malformed/missing entries throw rather than claim successful deletion. Exact console errors and permission checks are unverified; the public binding's NoPermission value is not substituted for unrelated host failures.
- [Initialization](../../../core/libs/prx/libSceContentDelete/Export.cpp) retains host allocation and does not emulate a private heap of the requested size. Reserved fields and heap size are not interpreted. Null parameters and invalid lifecycle calls are rejected.
- [Filesystem failures](../../../core/libs/prx/libSceContentDelete/Export.cpp) are reported as exceptions. Removal is not transactional: an I/O failure after earlier files were removed can leave a partial bundle requiring host cleanup. Preflight is not protection against a hostile process replacing filesystem entries between checks and removal. The mutex serializes this module's calls, not external processes. Crash recovery, console equivalence and POSIX runtime behavior have not been validated. The 4/4 implemented-export count is not a measurement of those properties.
